website summary

This lecture explains why programmers should spend time learning a powerful editor. Writing code is not just typing text continuously. Most of the time we jump between files, read code, search, move around, and make small changes. A good editor should make these actions fast.

The page introduces Vim as a command-line editor with a long history from Vi. The main idea is that Vim is modal and composable. Different modes give the same key different meanings, and commands can be combined like a small language. For example, a motion such as w means moving by word, and an operator such as d means delete. Together, dw means delete one word.

The lecture starts with basic modes, then teaches buffers, windows, command-line commands, motions, selections, editing operators, counts, text objects, customization, plugins, Vim modes in other tools, and advanced features such as search-and-replace and macros.

The most important idea is not to memorize everything at once. Learn the basic model first, use Vim for real editing, and search for better commands whenever an operation feels repetitive.

learning path

  1. Run vimtutor.
  2. Learn normal mode, insert mode, save, quit, and basic movement.
  3. Practice operators and motions: dw, cw, d$, ci(.
  4. Use search instead of moving manually.
  5. Learn splits and buffers.
  6. Add a small .vimrc.
  7. Learn macros when editing becomes repetitive.

The core habit is simple: when an edit feels slow, ask whether Vim has a command for it. Usually it does.
