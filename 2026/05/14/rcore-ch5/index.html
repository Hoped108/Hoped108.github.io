Where TCB, Page Tables, Stacks, and Variables Live

This note answers one question: in rCore, where are data structures such as
TaskControlBlock, PageTable, local variables, kernel stacks, user stacks,
and ELF-loaded program data stored?

Local Variables

Small local values such as:

usually live on the current stack, unless the compiler optimizes them into
registers.

When the CPU is running kernel code, these local variables use the current
kernel stack. When it is running user code, they use the current user stack.

The compiler decides the function stack-frame layout, such as whether a value is
stored at sp - 8, sp - 16, or only in a register.

User Stack

The user stack is not directly stored in the ELF. The kernel creates it after
loading the ELF segments.

In MemorySet::from_elf, the kernel finds the end of the ELF-loaded region,

Here entry_point comes from the ELF, while user_sp is the user stack top

Summary

The loader’s role is to provide ELF data to the kernel. The ELF describes the
user program layout, while the kernel creates the address space, page tables,
trap context, and stacks needed to run the program.
