address.rs

va pa ppn vpn => usize(struct)
实现四个结构体的usize封装，然后，实现From trait => usize

实现基本的上取整，下取整，取offset，判断对其的function

这样就可以实现从va 到 vpn之间的转换 From和into
因为rust不提供自动类型转换，所以需要手动实现，同时也要判断或者取整，否则编译器会报错

=>将vpn转成一个数组，【0，1，2】每个数组元素表示页表索引 idx[i] = vpn & 511;表示取页表的低9位 因为vpn是27位usize

循环最先得到vpn[0],但是查询是从vpn[2]开始的

memory_set.rs

使用lazy_static!定义了static ref KERNEL_SPACE: Arc<UPSafeCell<MemorySet>>
再次封装一个MemorySet结构体

主要实现了
from_elf: build a user process from a elf data file.extra the elf and then build the stack,heap start area for sbrk,trap context => return :(memory_set,user_stack_top,entry_point)
activate: get root_ppn and write into the satp register => return the sfence.vma(to flush the ole TLB)
translate: use page_table.translate
shrink_to & append_to: unmap/map call memory_area shrink_to & append_to => map/unmap => map_one/unmap_one(one by one) just to use page table’s new and empty() a pte.By the way,create a frame if not found.

frame_allocator.rs

package the ppn as FrameTracker

=> have the drop mechanism,so when the FrameTracker disappear,Rust would call drop and return the physical page to frame_allocator

定义一个静态全局变量，frame_allocator

然后封装一下pub 函数 如init alloc dealloc

FRAME_ALLOCATOR分配的实际frame来自这里

sv39中ppn是44bits，而pa是56bits 这里就是管理整个page frame，然后整个recycled放的是被回收的ppn
又因为已经实现了heap_allocator，所以在heap_space中，可以分配个这个Vec：recycled当作heap来放置ppn

heap_allocator 管理内核数据结构的内存；frame_allocator 管理物理页帧。FRAME_ALLOCATOR 可能用 heap 存自己的管理信息，
但它分配出去的 frame 不来自 HEAP_SPACE。

mm 里面就是对 address中的各种地址进行封装，封装所有权，迭代器，同时结合flag 封装page table
