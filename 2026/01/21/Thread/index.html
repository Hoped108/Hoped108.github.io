线程中断

本质

interrupt()是一个Thread的实例方法，用来中断实例化的对象线程，但是中断的本质是修改状态标签，状态标签是Thread类维护的一个对象。

API

理解interrupt()必须结合的方法

方法 作用 是否清除中断标志位
thread.interrupt() 请求中断线程（置标志位/唤醒阻塞线程） 否（除非触发阻塞异常）
thread.isInterrupted() 读取当前线程的中断标志位（仅读取，不修改） 否
Thread.interrupted() 读取当前线程的中断标志位，并清除标志位（静态方法，针对当前线程） 是

规则

  • 1、【阻塞状态】（sleep/wait/join/park）
    • 立即抛出InterruptedException，然后清除原本阻塞的标志位
  • 2、【运行状态】
    需要由线程自己来判断是不是要中断，只是将状态标签修改成true

输出：

👉 结论：运行线程被中断，只是贴了个标签，必须线程自己 “看标签、做决策”（比如退出循环），才会停。

为什么这么设计

  • 1、Java 不允许 “强制终止线程”（比如废弃的 stop() 方法），因为强制终止会导致线程持有的锁、资源没释放（比如打开的文件、连接），引发内存泄漏、数据错乱。而 interrupt() 是 “协作式” 的：线程自己知道什么时候能停（比如执行完一次任务、释放完资源后），既安全又灵活。

  • 2、 比如你写一个下载线程，收到中断信号后，可以先暂停下载、关闭网络连接、删除临时文件，再退出 —— 这就是优雅中断。
